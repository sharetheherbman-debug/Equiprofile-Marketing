## Dependencies and defaults

The SQL files must be read as historical artifacts, not as a reliable linear chain. Their table-level dependencies are represented by each `ALTER TABLE`, `FOREIGN KEY`, and `CREATE TABLE` operation in the mechanical audit above. Defaults, constraints, and data operations remain exactly as written in the preserved source files; a supported upgrade must use an explicitly recognised database fingerprint rather than inferring that these historical effects occurred.

## Required next step

Create a deterministic final-Core schema manifest and read-only baseline inspector. Only a fingerprint that exactly matches a named supported baseline can be considered for a separately explicit, operator-authorised adoption step. Partial, unknown, ambiguous, or drifted schemas must be rejected without mutation.
